## 引擎目录大小级联同步开关: 宿主侧补下发

用户口径: "引擎初始化完成后, 需要 xjs_db_SetParentSizeSync 为真"。此前宿主**一次都没下发过**
该开关 (grep 只命中 xunjieso.h 声明), 引擎侧恒为默认关闭 = 目录大小只统计直接子文件,
文件同步时大小变更不向上级目录级联。

改动两处:
1. `main.cpp` WM_CREATE 主窗 `xjs_SetDefaultEngine(g_engine)` 之后立刻
   `xjs_db_SetParentSizeSync(g_engine, TRUE)` —— **必须在 xjs_db_Load / xjs_db_ScanPath 之前**。
   引擎头文件口径: "遍历中途或事后开启会立即对现有数据重算生效", 放到加载完成之后就变成拿
   450 万行旧库白级联重算一遍; 此刻库为空, 置真零成本。
2. `xjs_engine.cpp` `XjsEngineApplySavedConfigs()` 开头加**幂等兜底**:
   `if (!xjs_db_IsParentSizeSync(g_engine)) xjs_db_SetParentSizeSync(g_engine, TRUE);`
   纯防御 (防引擎重建/未来新增下发点漏设); 绝不能无条件重下 —— 那会在加载路径拿旧库重算,
   且 35=库忙时连开关一起废掉。

编译验证: rc=0 / cl=0 (20 TU) / link=0, exe 1802752 字节。

### 本次 PowerShell 复刻编译的两个新坑 (补充"构建环境"节)

- **cl/link 在默认沙箱内跑不出 obj** (exit 为空 + obj=0 + 输出文件 0 字节, 但不报错) →
  必须 `dangerouslyDisableSandbox: true`。注意 `cl /?` 在沙箱内却正常返回 20906 字节,
  所以"能不能跑"的探测会误判, 直接看 obj 数量 / exit 才是真信号。
- **link 参数里的中文路径不能手工加引号**: 写成 `"D:\...\main.res" xunjieso.lib comctl32.lib ...`
  会被 PowerShell 合成**单个**参数 → `LNK1181 无法打开输入文件 "…main.res xunjieso.lib …"`。
  正确做法: obj/res/lib 逐个 `$argl += $path` 不加引号 (数组传给原生 exe 时自动加引号)。

## 症状: "xjs_result_Query() 搜索时,主线程不能进行搜索等待哦!" 弹窗 — ABI 错配

现象: 用户报该弹窗, 且"之前是没有的"。**根因不是调用点写错, 而是 exe 与 dll 版本错配**:
用户重编了 `xunjieso.dll` (10-08 05:39, 5 参签名), 但 `SnailQuickSearch.exe` 还是
10-07 23:33 的旧构建 (按 4 参调用)。x64 调用约定下前 4 参走寄存器, 第 5 参 `waitComplete`
读到栈上残留垃圾值 → 非 0 → 等价于 `waitComplete=TRUE` → 主线程发起搜索被引擎拦下弹窗。
第 4 参 `FALSE`(0) 恰好等价 NULL, 所以过滤没出问题, 只有 waitComplete 炸。

定位手法(可复用): `python -c` 在 dll/exe 里搜报错文案的 utf-16-le 编码 → 只有 dll 命中
(偏移 5219334), exe 无 → 确认是引擎侧弹窗而非宿主, 直接指向 ABI 不一致。

修复: 重编宿主 exe + 部署版 `plugins/ai-assistant/ai-assistant.dll` (它也是 10-07 的 4 参构建,
同样会炸)。两者重编后弹窗根除。宿主 rc/cl/link 全绿(LINK_EXIT=0), 插件 rc/cl 全绿并已
copy 到 `plugins/ai-assistant/`。

**教训**: 改 `xunjieso.h` 的导出签名后, 必须把仓库里每个**独立链接进 xunjieso.lib 的二进制**
全部重编 (宿主 exe + 插件 dll), 只改头文件调用点是不够的。

## AI 插件接入「限定目录」参数 (run_search)

把引擎的 `SearchFilterConfig` 通路暴露给模型, 让 AI 自己决定搜索范围。参数名 **「限定目录」**,
旧名「目录范围」「搜索目录」兼容读取。

- **形态宽容** (同「搜索分类」口径): 字符串(顿号分隔) / 字符串数组 / 对象数组
  `[{"路径":"D:\\工作","递归子目录":false}]` — 只有对象数组能关递归, 默认 true。
- **构造**: `AgentScopeFilterJson()` (ai_agent.cpp) → `{"包含路径":[{"路径":..,"递归子目录":..}]}`。
- **校验**: 通配符 / 相对路径当场报错 (引擎按字面匹配, 传错会静默 0 条, 让模型拿到 count=0 再猜);
  路径去重保序。
- **引擎只有白名单**: dll 里核过只有「包含路径」「递归子目录」两个键, **无排除项** — "排除某目录"
  只能列其余目录或退回 SQL NOT LIKE, 这条已写进提示词。
- **落地链路**: `AiToolStep::scope` (std::string UTF-8 引擎 JSON 原文, 与 res8/arg 同口径) →
  落库 `os["限定目录"]` / 读取 `U8(jst.S(...))` / `operator==` / 历史回喂 `HistStepArgsOf` /
  卡片徽标 `.sscope` (emerald 绿, 与 `.sflt` 分类徽标区分) / `AgentManualExec` 重放透传。
- **提示词两处**: 工具 description 加参数说明 + "用户提到目录/盘时用本参数而不是写进搜索词";
  `AI_INSTRUCTIONS` 新增《限定目录（搜索范围的正确做法）》整节 (6 条: 用法/取值/五模式都生效/
  无排除项/目录没索引会搜 0 条/内容搜索优先用它); `BuildEnvSnapshot` 加一行**可用固定盘符**
  (GetDriveTypeW 扫 A-Z, 模型否则只能猜盘符)。

**坑**: `AI_TOOLS_JSON` 是 R"json( 分两段拼接的, 改完必须用 python `json.loads` 校验;
英文双引号在 JSON 字符串里需转义 (我踩了一次, 改用中文「」); C++ 源码里 `D:\\工作` 写多一层会
变成 `D:////工作` 被模型看到。**注意 `--accent-green` 不存在, 实际是 `--accent-emerald`**。
